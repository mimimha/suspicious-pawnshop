# PRD 4-2 — 월세 납부와 STAGE 결과

> 출처: Notion `통합 기획서` §2~4·§35~39, `전체 게임 진행 및 스테이지 구조` §7·§10·§12~14, `가격 및 경제 밸런스` §3~7, `전당포 게임 기획 개요` §2·§4·§6~8
> 작성일: 2026-08-19 (Notion 페이지 기준 시각 2026-08-18T14:47Z)
> 이전 PRD: `docs/prd/step-04/prd-4-1-bag-merchant.md`

## 목표

보따리 상인 거래 종료 직후 월세를 현금으로 자동 판정한다. 납부에 성공하면 월세를 차감하고 현금·재고를 다음 STAGE로 이월하며, 실패하면 부족 금액과 GAME OVER를 표시한다. 데모 마지막인 STAGE 2까지 성공하면 DEMO CLEAR로 전체 플레이 루프를 완결한다.

## 사용자에게 보이는 최소 플레이 흐름

```text
보따리 상인 거래 종료
  → 셔터 재하강
  → 아이템 상점
  → 아이템 상점 종료
  → 현재 현금과 STAGE 월세 비교
  ├─ 현금 ≥ 월세
  │    → 월세 자동 차감
  │    → 최종 정산 명세서
  │    → STAGE 1: 현금·재고 이월 후 STAGE 2 DAY 1
  │    → STAGE 2: DEMO CLEAR
  └─ 현금 < 월세
       → 부족 금액 표시
       → GAME OVER
```

## 구현 범위

### 1. STAGE 월세 설정

- 월세는 STAGE별 config에서 관리한다.
- STAGE 1 월세는 현재 테스트값 22,000원이다(2026-08-26 조정, 이전 24,000원).
- STAGE 2 월세는 현재 테스트값 35,000원이다(2026-08-26 조정, 이전 40,000원).
- 시작 자금 55,000원은 STAGE 1 월세를 넘지만, 두 STAGE 월세 합(64,000원)보다 적다.
  즉 거래로 자산을 늘리지 않으면 STAGE 2 월세를 낼 수 없다.
  즉 거래로 자산을 늘려야 STAGE 2를 시작할 수 있다. (이전 서술: 시작 자금 40,000원 · 월세 50,000원으로 10,000원
  부족해 반드시 수익 활동이 필요하다.
- 데모 마지막 STAGE는 2로 config에서 관리한다.

### 2. 월세 판정과 현금 처리

- 보따리 상인의 `상인 거래 종료` 뒤 셔터 재하강과 아이템 상점을 거치고, 상점을 닫는 즉시 별도 확인 버튼 없이 한 번만 자동 판정한다.
- 현재 현금이 월세 이상이면 월세 전액을 차감한다.
- 현재 현금이 월세보다 적으면 현금을 차감하지 않고 실패 처리한다.
- 재고의 평가 금액은 월세 납부 능력에 포함하지 않는다.
- 월세 납부를 미루거나 빚·대출로 전환할 수 없다.
- 월세 결과는 중복 적용할 수 없다.

### 3. 최종 정산 명세서

- DAY 3의 최종 명세서에 다음 항목을 표시한다.
  - 일반 판매 수익
  - 보따리 상인 판매 수익
  - 물건 매입 비용
  - 월세
  - 월세 전 보유 현금
- 성공 시 월세 납부 후 이월금을 표시한다.
- 실패 시 보유 현금·납부할 월세·부족 금액으로 원인을 표시하고 별도의
  `월세를 납부하지 못했습니다.` 문장은 표시하지 않는다.
- 아직 없는 아이템 구매 비용과 병원비 항목은 표시하지 않는다.

### 4. STAGE 1 성공과 자원 이월

- 성공 명세서의 `다음 STAGE` 버튼을 누르면 STAGE 2 DAY 1 `BeforeOpen`으로 이동한다.
- 월세 납부 후 남은 현금과 판매하지 않은 재고를 그대로 유지한다.
- 재고 사용량은 유지된 재고로부터 그대로 계산한다.
- DAY, 영업시간, 당일 장부, 당일 시세, 손님 큐, 보따리 상인 제안은 초기화한다.
- 아직 구현되지 않은 소모품과 손님별 신뢰도 이월은 이번 PRD에서 다루지 않는다.
- STAGE 2의 가품·감정·공격·아이템은 이후 PRD에서 추가하며, 현재는 기존 기본 거래 루프로 진입한다.

### 5. 실패와 데모 완료

- 월세 실패 시 보따리 상인 이후 정산 흐름에서 `GAME OVER`를 표시하고, 월세 전 현금·월세·부족 금액을 안내한다.
- GAME OVER와 STAGE 결과 팝업은 감정 결과·제안 불가에 쓰는 공용 목재·황동 팝업 프레임과 공용 확인 버튼 에셋을 재사용한다.
- GAME OVER 뒤 거래·판매·DAY 진행 입력을 받지 않는다.
- `처음부터` 버튼으로 초기 자금·빈 재고·STAGE 1 DAY 1 상태의 새 게임을 시작할 수 있다.
- 사용자 승인 변경(2026-08-24): GAME OVER의 제목과 정산 내용은 기존보다 20px 아래로 이동하고,
  `처음부터` 버튼은 기존 위치보다 10px 위로 이동한다. 다른 STAGE 결과 팝업의 배치는 유지한다.
- STAGE 2 월세 납부 성공 시 다음 STAGE로 진행하지 않고 `DEMO CLEAR` 화면을 표시한다.
- DEMO CLEAR 화면에는 최종 잔액과 보유 재고 수를 표시하고 `처음부터` 버튼을 제공한다.

### 사용자 승인 변경 — 성공 결과 화면 정보 축약·배치 통일 (2026-08-25)

- STAGE CLEAR와 DEMO CLEAR는 GAME OVER와 동일하게 `결과 제목 → 상태 한 줄 → 핵심 수치
  2개 → 구분선 → 최종 결과 → 설명 → 행동 버튼` 순서로 표시한다.
- 성공 결과의 핵심 수치는 `목표 실현 손익`, `달성 실현 손익`만 남긴다.
- STAGE CLEAR의 최종 결과는 `이월 잔액`, DEMO CLEAR의 최종 결과는 `최종 잔액`으로 표시한다.
- 일별 일반 판매·상인 판매·물건 매입·병원비·월세 전 현금 등 세부 장부 항목은 성공 결과
  화면에서 제거하며, 장부와 일일 명세서의 실제 기록은 유지한다.
- 세 결과 화면의 제목·본문·구분선·버튼 위치와 텍스트 열 간격을 동일하게 사용한다.

## 범위 밖

- STAGE 2 가품·감정·공격·특수 아이템
- STAGE 2 신규 고가 물건과 손님 구성
- STAGE 3 이상
- 대출, 빚, 이자, 신용도
- 영구 성장, 저장·불러오기, 이어하기
- 최종 아트·사운드·연출

## 시스템 책임

- **GameState**: STAGE·DAY·진행 결과, 월세 차감, 다음 STAGE 전이, GAME OVER와 DEMO CLEAR.
- **Stage config**: STAGE별 월세와 데모 마지막 STAGE.
- **Inventory**: 성공 시 기존 재고 유지, 새 게임 시 빈 재고 생성.
- **Market / CustomerQueue / BagMerchant / DailyLedger**: 다음 STAGE에서 각자의 STAGE/DAY 상태 초기화.
- **DayScene**: 최종 명세서, 결과 화면, 다음 STAGE와 처음부터 버튼 연결.

## 완료 조건

1. 시작 자금 55,000원, STAGE 1 월세 22,000원과 STAGE 2 월세 35,000원이 config에서 관리된다.
2. 상인 거래 종료 직후 월세 판정이 정확히 한 번 자동 실행된다.
3. 현금이 월세 이상이면 정확한 월세가 차감된다.
4. 현금이 월세보다 적으면 현금은 유지되고 부족 금액이 정확히 계산된다.
5. 재고 가치는 월세 판정에 포함되지 않는다.
6. 성공 결과 화면에 목표·달성 실현 손익과 이월/최종 잔액이 간결하게 표시된다.
7. 실패 화면에 보유 현금·월세·부족 금액과 GAME OVER가 표시된다.
8. STAGE 1 성공 후 현금과 재고를 유지한 채 STAGE 2 DAY 1로 진입한다.
9. 다음 STAGE 진입 시 DAY 단위 상태와 상인 제안이 초기화된다.
10. GAME OVER 뒤 일반 게임 입력이 차단되고 `처음부터`로 초기 상태를 시작한다.
11. STAGE 2 성공 후 `DEMO CLEAR`가 표시되고 STAGE 3으로 진행하지 않는다.
12. 기존 전체 테스트와 `npm run typecheck`, `npm run build`, `npm test`가 통과한다.

## 승인 시 확정되는 사항

1. 월세는 상인 거래 종료 즉시 별도 확인 없이 자동 판정한다.
2. 실패 시 현금은 차감하지 않고 부족액을 표시한다.
3. STAGE 1 성공 시 현금·재고만 우선 이월하며 STAGE 2의 신규 규칙은 후속 PRD에서 붙인다.
4. STAGE 2 성공은 STAGE 3 진입이 아니라 DEMO CLEAR로 끝난다.

## 사용자 승인 변경 — STAGE 2 손익 목표 (2026-08-26)

- STAGE 2의 최소 실현 손익 목표를 0원에서 6,000원으로 올리고, STAGE 1은 3,000원에서 2,000원으로 낮춘다.
- 목표가 0이면 STAGE 1에서 벌어 둔 이월 자금만으로 STAGE 2를 무거래 통과할 수 있었다.
  마지막 STAGE가 데모의 절정이므로 거래를 요구한다.
- 통과 조건은 기존과 같다. 월세를 낼 현금과 최소 실현 손익을 **모두** 채워야 한다.
- 값은 통과율 시뮬레이션으로 잡은 현재 테스트값이다.
  최초 제시가의 75%부터 흥정하는 '보통' 플레이가 69%, 65%부터 부르는 '공격적' 플레이가 91% 완주한다.
- 목표 안내 팝업의 마지막 줄은 최종 STAGE 여부로 갈린다.
  최종 STAGE는 `데모를 완주한다`, 그 외는 `다음 STAGE로 간다`.
