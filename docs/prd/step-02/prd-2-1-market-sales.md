## 목표

Step 1의 `시세 확인 및 판매 준비` 임시 상태를 실제 경제 행동으로 대체한다. DAY가 시작될
때 카테고리별 시세를 한 번 갱신하고, 보유 물건 중 원하는 항목을 현재 판매가로 처분한 뒤
판매창을 닫아 영업을 시작할 수 있어야 한다.

이 PRD가 끝나면 핵심 루프인 `흥정하여 매입 → 다음 DAY 시세 확인 → 판매 또는 보유 → 현금
확보`가 처음으로 실제 플레이에서 연결된다.

## 사용자에게 보이는 최소 플레이 흐름

```text
DAY 시작
  → 카테고리별 당일 시세 갱신
  → 시세 확인 및 판매 팝업 자동 표시
      보유 물건 목록
      카테고리 시세 상태: 하락 / 보통 / 상승
      물건 선택
      매입가 / 오늘 판매가 / 손익 확인
      [보유] 또는 [판매]
  → 원하는 물건을 0개 이상 판매
  → [판매 종료 및 영업 시작]
  → 팝업 닫힘
  → 해당 DAY에는 일반 판매 불가
  → 손님 거래 시작
```

## 구현 범위

### 1. Market 시스템 — 순수 TypeScript

- Market이 카테고리별 전날/오늘 시세 배율과 갱신 책임을 소유한다.
- DAY가 시작될 때 카테고리별 배율을 정확히 한 번 생성한다.
- 같은 카테고리의 물건은 그 DAY 동안 같은 배율을 사용한다.
- 영업 중에는 시세가 변하지 않는다.
- 다음 DAY 갱신 시 오늘 배율을 전날 배율로 이동하고 새 오늘 배율을 생성한다.
- 테스트 가능한 난수 공급자를 주입할 수 있게 한다.

### 2. 카테고리별 시세 범위

| 유형 | 카테고리 | 현재 테스트 범위 |
| --- | --- | --- |
| 안정형 | 생활용품 | 기준가의 90~110% |
| 일반형 | 전자기기, 취미용품 | 기준가의 80~120% |
| 변동형 | 액세서리, 수집품, 골동품 | 기준가의 70~130% |

- 범위와 카테고리 매핑은 `src/config/`에서 관리한다.
- 판매가 공식은 `기준가 × 오늘 카테고리 시세 배율`이다.
- 판매가는 100원 단위로 반올림한다. **Notion 미명시 현재 테스트값**이다.

### 3. 공개 시세 상태

- 내부 배율은 플레이어에게 표시하지 않는다.
- 전날 대비 상태만 `하락 / 보통 / 상승`으로 표시한다.
- DAY 1은 비교 대상이 없으므로 모든 카테고리를 `보통`으로 표시한다.
- 전날 배율과 오늘 배율 차이가 ±5%p 이내면 `보통`, 그보다 낮으면 `하락`, 높으면
  `상승`으로 표시한다. **Notion은 '비슷한 상태'의 임계값을 정하지 않아 둔 현재 테스트값**이다.
- `급등` 상태는 만들지 않는다(통합 기획서와 `재고·판매·시세 규칙` 기준).

### 4. 판매 처리 — 순수 TypeScript

- Inventory에 `remove(instanceId)`를 추가한다.
- GameState에 `earnMoney(amount)`를 추가한다.
- 판매 처리 함수가 아래 작업을 한 번에 수행한다.
  1. 해당 재고 물건 존재 확인
  2. Market에서 판매가 계산
  3. Inventory에서 해당 인스턴스 제거
  4. GameState에 판매 대금 추가
  5. DailyLedger에 sale 기록 추가
- 존재하지 않거나 이미 판매한 instanceId는 다시 판매할 수 없다.
- 판매한 물건은 복구할 수 없다.

### 5. DailyLedger 판매 확장

- 기존 `purchase`에 `sale` 기록 타입을 추가한다.
- 파생값: `saleCount`, `salesRevenue`.
- `netCashChange = salesRevenue - purchaseExpense`로 확장한다.
- DAY 종료 명세서에 `일반 판매 +금액`을 추가한다.
- DAY 시작 판매가 해당 DAY의 장부에 포함된다.

### 6. DAY 시작 판매 팝업

- `BeforeOpen`에 진입하면 판매 팝업을 자동으로 표시한다.
- 단, 새 게임의 `STAGE 1 · DAY 1`은 판매할 재고가 0개이므로 판매 팝업과 오늘의 시세
  안내를 생략하고 일반 `영업 시작` 버튼을 표시한다.
- 이후 DAY와 STAGE에서는 재고가 비어 있어도 기존 판매 단계를 유지한다.
- 보유 물건마다 이름, 카테고리, 시세 상태를 목록/격자로 표시한다.
- 각 판매 슬롯에는 해당 매입품의 실제 이미지를 표시하고, 이름·카테고리·시세 방향·오늘
  판매가를 함께 배치한 카드 형태로 구성한다.
- 선택한 카드는 금빛 테두리와 밝은 배경으로 강조하며, 빈 슬롯은 낮은 명도의 빈 카드로
  유지해 전체 재고 용량과 보유 위치를 한눈에 알 수 있게 한다.
- 사용자 제공 레퍼런스를 기준으로 판매창을 좌측 세로 재고 목록과 우측 선택 물건 상세 영역으로
  나눈다. 우측에는 큰 물건 이미지, 현재 판매가, 손익, 최근 시세 그래프와 내일 시세 확인 영역을 둔다.
- 하단에는 `시세 확인`, `판매`, `영업 시작`을 동일한 크기의 주요 행동 버튼으로 나란히 배치한다.
- 9칸 재고는 좌측 목록에 한 페이지당 5칸씩 표시하고 페이지 버튼으로 전환한다.
- 판매할 매입품이 없으면 안내 문구를 좌측 목록 종이 영역 중앙에 표시하고, 우측 상세 영역은 비운다.
- 보유 매입품이 5개를 초과해 페이지가 나뉠 때만 페이지 화살표와 페이지 번호를 표시한다.
- 사용자 승인 변경(2026-08-24): 기존 색상과 채도, 검정 목재·황동·종이 팔레트는 유지하되
  반복 문양, 과도한 표면 노이즈, 중첩된 테두리와 코너 장식을 줄인다. 선택 행·페이지 버튼·
  하단 행동 버튼은 얇은 단일 황동선과 평탄한 면 중심으로 표시해 정보 가독성을 우선한다.
- 하단 세 버튼은 아이템 구매창의 자주색 가죽·황동 테두리 버튼 에셋을 공통 재사용해 재질과
  모서리 형태를 통일한다. 에셋 하단의 회색 반투명 그림자는 제거하며, 세 기능은 런타임 문구로
  구분하고 원본 버튼 비율을 유지한다.
- 하단 행동 버튼 묶음은 오른쪽 외곽선에 붙지 않도록 상세 영역 중앙 쪽으로 정렬한다.
- 패널별 명암 차이와 절제된 재질감으로 깊이를 만들고, 촘촘한 스크래치·양각 무늬는 사용하지 않는다.
- 물건 선택 시 매입가, 오늘 판매가, 예상 손익을 표시한다.
- `판매`는 선택 물건 하나를 즉시 판매한다. 확인 정보가 이미 같은 팝업에 있으므로 별도의
  2차 확인 팝업은 만들지 않는다.
- 판매 후 목록, 현금, 재고 수량을 즉시 갱신한다.
- 매입 성공 시 물건명, 매입가, 재고 칸, 진품 여부 확인 상태를 약 2초간 비모달로 표시한다.
  `좋은 거래`·`위험한 거래`처럼 플레이어의 판단을 대신하는 평가는 붙이지 않는다.
- 판매 완료 시 매입가, 판매가, 실현 손익, 보유 기간을 함께 표시하고 가품 결과를 알린다.
- 시세 확인권으로 공개한 다음 DAY 예상가는 해당 재고 인스턴스에 기록한다. 확인권을 쓰지
  않았다면 과거 시세 정보를 임의 생성하지 않고 `미확인`으로 유지한다.
- 거래 기록 화면은 최근 매입·판매 내역과 누적 거래 수, 이익·손실 건수, 평균 실현 손익을
  표시한다. 평가 등급이나 정답 판정 문구는 사용하지 않는다.
- 거래 기록 팝업은 아이템·매입품 팝업과 같은 검정 목재, 얇은 낡은 황동선, 어두운 자주색
  재질을 사용한다. 상단에는 매입·판매·이익·손실·평균 손익을 다섯 칸으로 나누고, 최근 거래는
  아래의 다섯 개 장부 행에 한 건씩 표시한다.
- 매입 성공은 금빛, 가품 발견과 손실은 적색, 큰 수익은 녹색 결과 카드와 짧은 확대·복귀
  연출로 강조한다. 큰 수익·큰 손실 기준은 config의 현재 테스트값으로 관리한다.
- 매입품이 판매되면 남은 물건은 현재 슬롯의 상대 순서를 유지한 채 첫 칸부터 빈칸 없이
  앞으로 자동 정렬된다. DAY 시작 판매 목록과 매입품 보관창에 동일하게 반영한다.
- `영업 시작`을 누르면 판매 팝업이 닫히고 셔터 상승 연출을 재생한다. 셔터가 완전히
  열린 뒤 `GameState.openShop()`으로 진입하고 첫 손님과 영업 타이머를 시작한다.
- 판매창을 닫은 뒤에는 해당 DAY가 끝날 때까지 다시 열 수 없다.

### 7. DAY 전환 연결

- 게임 시작 DAY 1에 최초 시세를 생성한다.
- PRD 1-4의 `다음 DAY` 버튼으로 DAY가 증가하면 새 DAY 시세를 갱신하고 판매 팝업을 연다.
- 현금과 판매하지 않은 재고는 그대로 유지한다.
- 판매하지 않은 물건은 새 DAY 판매가로 다시 평가된다.
- DAY 3에도 영업 시작 전 일반 판매 기회가 존재한다.

## 시스템 책임

- **Market**: 카테고리별 시세 생성, 전날 비교 상태, 판매가 계산.
- **Inventory**: 보유 물건과 제거.
- **GameState**: 판매 수익만큼 현금 증가.
- **DailyLedger**: 일반 판매 수익 기록과 하루 합계.
- **DayScene**: 판매 팝업 렌더링과 시스템 호출 조정.

Market은 Inventory, GameState, Phaser에 직접 의존하지 않는다.

## 완료 조건

1. DAY 시작마다 카테고리별 시세가 정확히 한 번 갱신된다.
2. 시세 배율이 카테고리별 config 범위 안에서 생성된다.
3. 같은 카테고리 물건은 같은 DAY에 같은 배율을 사용한다.
4. DAY 1은 `보통`, DAY 2부터 전날 대비 `하락/보통/상승`이 표시된다.
5. 판매 팝업에서 물건의 매입가, 판매가, 예상 손익을 확인할 수 있다.
6. 판매하면 Inventory에서 해당 물건만 제거되고 현금이 판매가만큼 증가한다.
7. 판매 수익이 DailyLedger와 일일 명세서에 반영된다.
8. 판매하지 않은 물건은 다음 DAY까지 유지되고 새 시세로 재평가된다.
9. 판매창 종료 후 같은 DAY에는 다시 일반 판매할 수 없다.
10. 새 게임 STAGE 1 DAY 1에 재고가 없으면 판매창 없이 영업 시작 화면이 표시된다.
11. `npm run typecheck`, `npm run build`, `npm test`가 통과한다.
12. 판매창의 보유 슬롯에 실제 매입품 이미지와 오늘 판매가가 표시되고 선택 상태가 명확하다.

## 사용자 플레이테스트 항목

1. DAY 시작 시 판매창이 자동으로 나타나는 흐름이 자연스러운가
2. 물건별 시세 상태, 매입가, 판매가, 손익이 한눈에 이해되는가
3. `지금 판매`와 `다음 DAY까지 보유` 중 고민할 정보가 충분한가
4. 판매 후 현금 증가와 재고 제거 피드백이 명확한가
5. `판매 종료 및 영업 시작`이 판매 기회를 닫는 중요한 선택으로 느껴지는가
6. 다음 DAY에서 남긴 물건의 시세 상태/판매가 변화가 의미 있게 느껴지는가

## 현재 테스트값

| 값 | 현재값 | 출처 | 비고 |
| --- | --- | --- | --- |
| 안정형 시세 | 90~110% | 통합 기획서 §6 | 범위는 기획값, 세부 분포는 균등 테스트값 |
| 일반형 시세 | 80~120% | 통합 기획서 §6 | 동일 |
| 변동형 시세 | 70~130% | 통합 기획서 §6 | 동일 |
| 보통 판정 폭 | 전날 대비 ±5%p | Notion 미명시 | 현재 테스트값 |
| 판매가 반올림 | 100원 단위 | Notion 미명시 | 현재 테스트값 |

## 승인 시 확인할 가정

1. DAY 1 시세 상태는 비교 대상이 없어 모두 `보통`으로 표시한다.
2. `보통` 판정 폭은 전날 배율 대비 ±5%p로 시작한다.
3. 판매가는 100원 단위 반올림한다.
4. 개별 판매는 같은 화면의 손익 정보를 확인한 뒤 `판매` 한 번으로 즉시 확정한다.

위 값과 UX는 플레이테스트로 조정하며 모두 config 또는 UI 흐름에 분리한다.
