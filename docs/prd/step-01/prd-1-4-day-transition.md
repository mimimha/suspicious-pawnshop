## 목표

Step 1에서 만든 영업·거래·재고 흐름을 하루 단위 Vertical Slice로 완성한다. 영업시간이
끝나면 당일 매입 내역을 영수증 형태로 확인하고, 확인 버튼으로 다음 DAY의 `시세 확인 및
판매 준비` 상태에 진입할 수 있어야 한다. 현금과 재고는 다음 날에도 유지한다.

이 PRD는 실제 시세 생성과 판매를 구현하지 않고, 다음 Step에서 판매창을 연결할 명확한
진입점까지만 만든다.

## 사용자에게 보이는 최소 플레이 흐름

```text
게임 최초 진입
  → 닫힌 전당포 셔터 + [게임 시작]
  → [게임 시작] 클릭
  → 셔터 상승
  → DAY 1 영업이 즉시 시작되고 첫 손님 등장
  → DAY N 영업 중
  → 영업시간 종료
  → 셔터가 내려오는 전환
  → DAY N 일일 명세서
      정산서가 먼저 나타난 뒤 잠시 후 도장이 찍힘
      매입 건수
      물건 매입 비용
      오늘 현금 변동
      마감 현금
  → [다음 DAY]
  → 닫힌 셔터 위에서 DAY N+1 시세 확인 및 판매 준비
      보유 현금·재고 유지
      [영업 시작]
  → 판매 단계를 마치면 셔터 상승
  → DAY N+1 영업 시작
```

DAY 3 종료는 기존과 동일하게 `STAGE 1 종료` 임시 종착점에 머문다. 보따리 상인·월세·최종
명세서는 후속 PRD에서 대체한다.

## 구현 범위

### 1. 하루 거래 기록 — 순수 TypeScript

- `DailyLedger`가 현재 DAY의 현금 변동 기록을 소유한다.
- PRD 1-4에서 실제로 발생하는 기록은 `purchase` 한 종류다.
- 구매 성공 시에만 `{ type: 'purchase', itemName, amount }`를 기록한다.
- 재고 부족, 거래 포기, 결렬은 기록하지 않는다.
- 합계 파생값: `purchaseCount`, `purchaseExpense`, `netCashChange`.
- 다음 DAY로 넘어갈 때 이전 명세서 확인이 끝난 뒤 ledger를 초기화한다.
- 판매 수익·아이템 구매·병원비 필드는 아직 만들지 않는다. 실제 기능 PRD에서 기록 타입을
  추가한다.

### 2. 일일 명세서 데이터

#### 사용자 승인 시각 변경 — 세로형 도장 명세서

  어울리는 세로형 종이 전표로 재디자인한다.
- 사용자 승인 변경(2026-08-23): 화면 상단 제목은 `오늘 하루 명세서` 대신 `정산서`로 표시한다.
- 완성 목업과 실제 게임용 분리 에셋을 함께 제작한다. 분리 에셋에는 DAY, 금액, 건수 등
  동적 텍스트를 포함하지 않고 Phaser에서 실시간 렌더링한다.
- 정산 완료 시 별도 분리된 붉은 잉크 도장 에셋을 찍는 짧은 시각 피드백을 사용할 수 있게 한다.
- 명세서 종이, 제목 장식, 구분선, 도장, 다음 DAY 버튼 바탕은 독립적으로 교체할 수 있어야 한다.
- 사용자 승인 변경(2026-08-23): 제목과 겹치는 상단 장식 그림은 표시하지 않는다. 최대 이익·손실
  행과 마감 현금 프레임 사이에 충분한 간격을 두도록 마감 현금 영역을 아래로 내리고, 하단
  `다음 DAY` 버튼은 기존 위치보다 20px 위에 배치한다.

- 영업 시작 시점의 현금을 `openingMoney`로 기록한다.
- 영업 종료 시 `closingMoney`를 기록한다.
- 명세서에는 아래 값만 표시한다.

| 항목 | 계산 |
| --- | --- |
| 매입 건수 | 성공한 구매 기록 수 |
| 물건 매입 | 구매 금액 합계, 음수 표시 |
| 오늘 현금 변동 | `closingMoney - openingMoney` |
| 마감 현금 | 영업 종료 시 GameState.money |

- 명세서 합계가 실제 GameState 자금 변화와 일치해야 한다.

### 3. 영업 종료 전환

#### 사용자 승인 시각 변경 — 아이템 상점 상품 그리드 정렬

- 아이템 상점의 네 상품은 책 안쪽 안전 여백을 기준으로 동일한 2×2 셀에 배치한다.
- 선택 배경은 페이지 테두리나 중앙 제본선을 침범하지 않고 각 셀 안쪽에서만 다른 색으로 표시한다.
- 각 셀의 이미지·이름·보유 수량·가격은 같은 세로 기준선을 사용하고, 가격을 포함한 모든 문구는
  셀과 책 하단 테두리 안에 유지한다.
- 상품 이미지는 원본 종횡비를 유지한 채 동일한 최대 표시 영역 안에서 맞춘다.

- 타이머 종료 또는 개발용 `S` 영업 종료 모두 같은 종료 흐름을 사용한다.
- 수동 장사 종료와 타이머 종료 모두 DAY 1~3에서 예외 없이 셔터 하강을 먼저 재생한다.
- 진행 중 손님은 PRD 1-2 규칙대로 미성사 처리되고 명세서에 포함되지 않는다.
- `Closed` 진입 시 거래 UI를 숨기고 셔터가 완전히 내려온 뒤 일일 명세서·아이템 상점 또는
  마지막 DAY의 보따리 상인 화면을 표시한다.
- 샤따 전환은 `public/assets/overlays/pawnshop-roll-shutter.png`를 사용한다.
- 셔터는 화면의 왼쪽 끝부터 오른쪽 고정 벽이 시작되는 지점까지 완전히 덮는다.
- 오른쪽 고정 벽 약 180px만 셔터 영역에서 제외하고, 왼쪽 HUD·메뉴는 모두 셔터 뒤로 가린다.
- 영업 종료 시 셔터가 위에서 아래로 내려오며, 다음 DAY 진입 시 반대로 올라가 현재 플레이
  화면을 드러낸다.
- 전환 시간은 config의 현재 테스트값으로 분리한다.
- 전환 중에는 명세서 버튼을 누를 수 없다.

### 4. 다음 DAY 진입

- 명세서의 `다음 DAY` 버튼을 누르면 `GameState.advanceToNextDay()`를 호출한다.
- 현금과 Inventory 객체는 그대로 유지한다.
- ledger와 영업 시작 현금만 다음 DAY 기준으로 초기화한다.
- 상태 전환 뒤 셔터는 닫힌 상태를 유지하며 그 위에 시세 확인 및 판매 화면을 표시한다.
- 판매 화면의 `영업 시작`을 누르면 판매 화면을 닫고 셔터를 올리며, 상승 중 입력을 막는다.
- 셔터가 완전히 열린 뒤 `Open`으로 전환하고 첫 손님과 영업 타이머를 시작한다.
- 실제 판매 기능이 없음을 명시하고 `판매 없이 영업 시작` 버튼으로 Open에 진입한다.
- 이 임시 버튼은 판매 시스템 PRD에서 실제 판매창 종료 행동으로 대체한다.

### 5. DAY 3 경계

- DAY 3 영업 종료 시 기존 `STAGE 1 종료`에서 멈춘다.
- DAY 3 명세서, 보따리 상인, 월세, GAME OVER는 이 PRD 범위 밖이다.
- 마지막 DAY 이후 `advanceToNextDay()`를 호출할 수 없는 기존 방어를 유지한다.

## 시스템 책임

- **GameState**: Day/Phase/Money 전이. 기존 책임을 유지한다.
- **DailyLedger**: 하루의 거래 기록과 합계를 소유한다.
- **Inventory**: DAY가 바뀌어도 같은 인스턴스로 유지된다.
- **DayScene**: Phase 변화 감지, 샤따 피드백, 명세서 렌더링과 다음 DAY 입력만 담당한다.

## 완료 조건

1. 영업 중 성공한 구매가 DailyLedger에 정확히 기록된다.
2. 포기·결렬·재고 부족 거래는 명세서에 포함되지 않는다.
3. 영업 종료 시 매입 건수, 매입 비용, 현금 변동, 마감 현금이 표시된다.
4. 명세서 합계가 실제 GameState.money 변화와 일치한다.
5. 타이머 종료와 `S` 단축키가 동일한 종료/명세서 흐름을 사용한다.
6. `다음 DAY`를 누르면 DAY가 증가하고 판매 준비 상태로 진입한다.
7. 현금과 Inventory가 다음 DAY로 그대로 유지된다.
8. 새 DAY의 ledger는 비어 있고 openingMoney가 이월 현금으로 설정된다.
9. DAY 3 이후에는 다음 DAY 버튼이 나타나지 않고 기존 종착점에 머문다.
10. `npm run typecheck`, `npm run build`, `npm test`가 통과한다.
11. 최초 진입에는 오른쪽 고정 벽을 제외한 영역에 닫힌 셔터와 게임 시작 버튼이 표시되고, 버튼을 누르면 셔터가
    올라간 뒤 별도 영업 시작 입력 없이 DAY 1 첫 손님이 나타난다.
12. 일반 DAY 종료 시 셔터가 내려오고 다음 DAY 진입 시 다시 올라간다.
13. 마지막 DAY 종료도 셔터가 완전히 내려온 뒤 보따리 상인 화면으로 이어진다.

## 사용자 플레이테스트 항목

5. 다음 DAY에서도 현금과 매입품이 유지되는 것이 명확한가
