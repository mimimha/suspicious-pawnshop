# PRD 1-1 — 기본 GameState와 하루 진행

> 출처: Notion `전당포 게임 > 통합 기획서` §3(기본 게임 흐름), §4(DAY 기본 규칙), §32(시간 처리), §33(DAY 종료)
> 출처: Notion `전당포 게임 > Codex/Claude 에게 알려줘야 할 프롬프트` §4 Step 1 / PRD 1-1
> 스냅샷: 2026-08-16 (Notion 페이지 기준 시각 2026-08-16T03:39Z)

## 목표

**하루가 시작되고 끝나서 다음 날로 넘어가는 최소 Vertical Slice**를 만든다.

이 PRD가 끝나면 게임에 "시간이 흐르는 뼈대"가 생긴다. 손님도 물건도 거래도 없지만,
`영업 전 → 영업 중 → 영업 종료 → 다음 날`이 실제로 동작하고 화면에서 확인된다.
이후 모든 시스템(거래·재고·시세)은 이 흐름 위에 얹힌다.

## 사용자에게 보이는 최소 흐름

```
게임 실행
  → [영업 전]  DAY 1 / 보유 현금 표시, "영업 시작" 버튼
  → 버튼 클릭
  → [영업 중]  남은 영업시간 카운트다운 (손님 없음, 빈 가게)
  → 시간 0
  → [영업 종료] "DAY 1 영업 종료" 표시, "다음 날" 버튼
  → 버튼 클릭
  → [영업 전]  DAY 2 ...
  → DAY 3 영업 종료 후에는 "STAGE 1 종료" 표시, 다음 날로 진행하지 않는다
```

화면에는 텍스트와 버튼만 있으면 된다. 아트, 샤따 연출, 배경은 이 PRD의 범위가 아니다.

## 구현 범위

### 1. Phase 상태 기계

DAY 하나를 3개 Phase로 관리한다. 통합 기획서 §3의 DAY 흐름 중
**시세·판매·거래를 제외한 뼈대**만 가져온다.

| Phase | 의미 | 다음 Phase로 가는 조건 |
| --- | --- | --- |
| `BeforeOpen` | 영업 전. 샤따 내려간 상태 | 플레이어가 "영업 시작"을 누름 |
| `Open` | 영업 중. 영업시간이 흐른다 | 남은 시간이 0이 됨 (자동) |
| `Closed` | 영업 종료 | 플레이어가 "다음 날"을 누름 → 다음 DAY의 `BeforeOpen` |

- 전이는 **정해진 순서로만** 일어난다. 역방향 전이나 건너뛰기는 없다.
- 전이 로직은 Phaser Scene이 아니라 **순수 TypeScript**로 둔다 (테스트 가능해야 한다).

### 2. GameState

게임 전체 흐름에 필요한 **최소 상태만** 소유한다 (CLAUDE.md 상태 관리 규칙).

- Stage / Day / 현재 Phase / Money
- Day 증가, Phase 전이 같은 상태 변경은 GameState를 통해서만 한다.
- Inventory·Market·Customer 상태는 **넣지 않는다.** 각 시스템이 소유한다.

### 3. 영업시간 타이머

- `Open` 진입 시 영업시간이 시작되고, 0이 되면 자동으로 `Closed`로 전이한다.
- `BeforeOpen` / `Closed`에서는 시간이 흐르지 않는다.
- 통합 기획서 §32의 "감정·공격·안내 중 시간 정지"는 해당 기능이 없으므로 이 PRD 범위 밖이다.

### 4. 밸런스 config 모듈

`src/config/`에 TypeScript 상수 모듈을 만들고, 아래 값을 로직에 하드코딩하지 않는다.

- STAGE당 DAY 수
- 하루 영업시간
- 시작 자금

이 PRD에서 실제로 쓰는 값만 넣는다. 월세·재고 크기 등은 해당 PRD에서 추가한다.

### 5. 최소 화면

- 현재 DAY, 보유 현금, 현재 Phase 표시
- `Open`일 때 남은 시간 표시
- Phase에 맞는 버튼 1개 (`영업 시작` / `다음 날`)
- 개발 편의용 **영업시간 즉시 종료 단축키**를 둔다.
  3분 × 3일을 매번 기다리면 검증이 불가능하다. 개발용임을 화면에 표시한다.

## 범위 밖

이 PRD에서 **구현하지 않는다.**

- 손님 등장, 거래, 흥정 (PRD 1-2)
- Inventory, 매입한 물건 (PRD 1-3)
- 시세 갱신, 판매창, 일일 명세서 정산 (PRD 1-4 이후)
- 보따리 상인, 월세 납부, STAGE 클리어/GAME OVER 판정
- STAGE 2 요소 전체 (가품·감정·아이템·공격)
- 샤따 연출, 배경 아트, 사운드, 애니메이션
- 세이브/로드
- DAY 3 종료 이후의 처리 — "STAGE 1 종료" 표시에서 멈춘다.
  이 표시는 이후 PRD에서 실제 정산 흐름으로 대체될 **임시 종착점**이다.

## 필요한 상태/데이터

### GameState가 소유하는 상태

| 항목 | 타입 | 초기값 | 비고 |
| --- | --- | --- | --- |
| `stage` | number | 1 | 이 PRD에서는 1 고정. 증가 로직 없음 |
| `day` | number | 1 | 1~3 |
| `phase` | `BeforeOpen` \| `Open` \| `Closed` | `BeforeOpen` | |
| `money` | number | 시작 자금 | 이 PRD에서는 변동 없음. 표시만 |

### 타이머가 소유하는 상태

| 항목 | 타입 | 비고 |
| --- | --- | --- |
| 남은 영업시간 | number (초) | `Open`에서만 감소 |

`money`는 이 PRD에서 바뀌지 않는다. 그래도 GameState에 두는 이유는,
거래·판매·월세가 모두 현금을 건드리므로 소유자를 처음부터 GameState로 고정하기 위해서다.

## 완료 조건

1. `npm run dev`로 실행했을 때 `영업 전 → 영업 중 → 영업 종료 → 다음 날` 전이가
   실제 화면에서 확인된다.
2. DAY가 1 → 2 → 3으로 증가한다.
3. 영업시간이 0이 되면 **자동으로** `Closed`로 전이한다.
4. DAY 3 영업 종료 후에는 다음 날로 넘어가지 않고 "STAGE 1 종료"를 표시한다.
5. STAGE당 DAY 수·영업시간·시작 자금이 config 모듈에서만 정의된다
   (로직 파일에 숫자 리터럴로 박혀 있지 않다).
6. `npm run typecheck`와 `npm run build`가 통과한다.

## 자동 검증 항목

단위 테스트는 **Vitest**로 작성한다 (`npm test` → `vitest run`).

| # | 항목 | 방법 |
| --- | --- | --- |
| 1 | 타입 오류 없음 | `npm run typecheck` exit 0 |
| 2 | 프로덕션 빌드 성공 | `npm run build` exit 0 |
| 3 | 단위 테스트 통과 | `npm test` exit 0 |
| 4 | Phase 전이 순서가 지켜진다 | `BeforeOpen → Open → Closed → (다음 날) BeforeOpen` 단위 테스트 |
| 5 | 잘못된 전이가 거부된다 | `BeforeOpen`에서 바로 `Closed`로 갈 수 없음을 단위 테스트로 확인 |
| 6 | Day 증가 | `Closed` → 다음 날 진행 시 `day`가 1씩 증가함을 단위 테스트로 확인 |
| 7 | Day 경계 | DAY 3 `Closed`에서 다음 날 진행이 차단됨을 단위 테스트로 확인 |
| 8 | config 참조 | 로직 파일에 `3`, `180`, `50000` 같은 리터럴이 없음을 grep으로 확인 |
| 9 | 개발 서버 응답 | `GET http://localhost:5173/` → 200 |

### 테스트 작성 규칙

- 테스트 파일은 대상 모듈 옆에 `*.test.ts`로 둔다 (예: `src/state/gameState.test.ts`).
- **Phaser에 의존하지 않는 순수 로직만 단위 테스트한다.** Phase 전이와 GameState가
  Phaser Scene과 분리되어야 하는 이유이기도 하다.
  Scene 렌더링·입력은 단위 테스트 대상이 아니라 플레이테스트 대상이다.
- `describe`/`it`/`expect`는 `vitest`에서 명시적으로 import한다 (전역 주입을 쓰지 않는다).
- 별도 `vitest.config.ts`를 두지 않는다. Vitest가 `vite.config.ts`를 읽으므로
  `@/` 별칭이 그대로 적용된다 (확인 완료).

## 사용자 플레이테스트 항목

구현 후 `ready_for_playtest` 상태로 멈추고 아래를 확인받는다.

1. "영업 시작" 버튼을 눌렀을 때 반응이 즉각적인가
2. 하루 영업시간 3분이 체감상 적절한가 — 지금은 빈 가게라 판단이 제한적일 수 있다.
   "너무 길다/짧다"는 인상만 남겨도 된다
3. 영업 종료 → 다음 날 전환이 답답하지 않은가
4. DAY / 보유 현금 / 남은 시간 표시가 한눈에 들어오는가
5. DAY 3 종료 시 "STAGE 1 종료" 상태가 이해되는가, 아니면 멈춘 것처럼 보이는가
