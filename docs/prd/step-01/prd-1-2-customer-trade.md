# PRD 1-2 — 손님 1명의 최소 거래 흐름

> §16(물건 카테고리), §17(물건 데이터), §19(STAGE별 물건 가격), §32(시간 처리)
> 스냅샷: 2026-08-18 (Notion 페이지 기준 시각 2026-08-16T03:39Z, 재조회로 내용 변경 없음 확인)
> 이전 PRD: `prd-1-1-game-state.md`

## 목표

PRD 1-1이 만든 `BeforeOpen → Open → Closed → 다음 날` 뼈대의 **`Open` 상태 안에 처음으로
실제 거래 상호작용을 연결한다.** 손님 1명이 등장해 물건 1개를 제시하고, 플레이어가 가격을
흥정해서 사거나 거절하고, 손님이 퇴장하는 흐름 전체가 실제로 동작해야 한다.

이 PRD가 끝나면 "빈 가게에서 시간만 흐르는" PRD 1-1 상태에서 벗어나, 게임의 핵심 루프인
**흥정**이 처음으로 플레이 가능해진다.

### 사용자 승인 변경 — 공통 결과 프레임 제목 위치

- 제안 불가와 공격 관련 안내가 공유하는 목재·황동 결과 프레임의 제목은 상단 장식과 간격을
  확보하도록 기존 위치보다 10px 아래에 표시한다.

## 사용자에게 보이는 최소 플레이 흐름

```
[Open] 영업 중 (타이머 흐름, PRD 1-1과 동일)
  → 손님 등장
      이름 / 제시 물건(이름·카테고리) / 최초 희망 가격 표시
  → 플레이어가 가격 제안 (숫자 입력, 보유 현금 이하만 가능)
  → 손님 반응 표시
      수락 → 거래 성사
      조금만 올려달라 / 불만 / 강한 불만 → 재제안 가능 (최대 3회)
  → 거래 결과
      성사 : 자금 차감, "구매 완료" 표시
      포기(플레이어) 또는 3회 소진(자동 결렬) : "거래 종료" 표시, 자금 변화 없음
  → 손님 퇴장
  → 다음 손님을 받을 수 있는 상태로 복귀
      (개발용 단축키로 재호출 — 자동으로 여러 손님이 이어지는 하루 루프는 이 PRD 범위 밖)
```

타이머는 PRD 1-1과 동일하게 `Open` 동안 계속 흐른다. 흥정 중이라고 시간이 멈추지 않는다
(통합 기획서 §32: "가격 고민 / 가격 입력 / 흥정" 중에는 시간이 흐른다).

## 구현 범위

### 1. Item 최소 데이터 (§16, §17, §19)

- 필드: `id`, `name`, `category`, `basePrice`(기준가)
- STAGE 1 아이템 시드 목록을 `src/config/`에 데이터로 둔다. 카테고리는 §16 6종 중 일부만
  사용해도 된다. 기준가는 §19 STAGE 1 범위(6,000~25,000원) 안에서 정한다.
- **넣지 않는 필드**: 진품/가품 여부(STAGE 1은 항상 진품이므로 이 PRD에서는 필드 자체를
  만들지 않는다 — STAGE 2 PRD에서 추가), 현재 시세(판매 시스템 범위 밖), 희귀도(§18의
  가중치 추첨 로직은 이 PRD 범위 밖 — 아래 "제외한 것" 참고).
- 손님에게 물건을 배정할 때는 시드 목록에서 **균등 랜덤 1개**를 고른다. 희귀도별 등장 비중
  가중치는 적용하지 않는다.

### 2. Customer 최소 데이터 (§8, §10)

- 필드: `id`, `name`, `item`(Item), `initialAskingPrice`(최초 희망 가격, 공개),
  `minAcceptablePrice`(최저 수용 가격, 비공개)
- **넣지 않는 필드**: 성격, 가품 관련 성향, 신뢰도, STAGE 2 공격 성향. 이 PRD의 손님은
  전부 동일한 규칙으로 반응하는 "무성향" 손님이다. 성향 차이는 이후 PRD에서 추가한다.
- `minAcceptablePrice < initialAskingPrice`가 항상 성립하도록 생성한다.

### 3. 거래 상태 기계 (§9, §12) — 순수 TypeScript

Phaser Scene에 규칙을 두지 않고, PRD 1-1의 `GameState`/Phase 전이와 같은 방식으로 분리한다.

| 상태 | 의미 | 다음 상태로 가는 조건 |
| --- | --- | --- |
| `Idle` | 대기 중인 손님 없음 | 손님 등장 트리거 |
| `Presenting` | 손님이 물건·희망가 제시, 아직 제안 없음 | 플레이어가 첫 가격 제안 |
| `Negotiating` | 흥정 진행 중 (1~3라운드) | 손님 수락 / 3라운드 소진 / 플레이어 포기 |
| `Resolved` | 거래 종료 (성사/거절/결렬) | 결과 표시 후 손님 퇴장 |

### 4. 가격 제안 (§10, §11, §12, §13)

- **입력 방식**: 자유 숫자 입력. 플레이어가 원하는 금액을 직접 입력해서 제안한다.
- **제안 상한**: 현재 `GameState.money`보다 높은 금액은 제안할 수 없다(§13). 초과 입력은
  거부하고 안내한다.
- **라운드 수**: 손님 1명당 최대 3회(§12).
- **반응 판정** (§11 표를 그대로 사용):

  | 제안가 | 반응 | 흥정 지속 여부 |
  | --- | --- | --- |
  | `minAcceptablePrice` 이상 | 수락 | 즉시 거래 성사 |
  | 최저 수용가의 90~99% | "조금만 더 올려 달라" | 라운드 소모, 재제안 가능 |
  | 최저 수용가의 70~89% | 불만 | 라운드 소모, 재제안 가능 |
  | 최저 수용가의 70% 미만 | 강한 불만 | 라운드 소모, 재제안 가능 |

- **조기 결렬(성향 기반) 미포함**: 통합 기획서 §11은 "손님 성향에 따라 1회차부터 결렬될
  수도 있다"고 명시하지만, 성향/신뢰도 시스템 자체가 이 PRD 범위 밖이므로 이번 PRD에서는
  적용하지 않는다(사용자 확인 완료). 3회 안에 `minAcceptablePrice`에 도달하지 못하면
  자동으로 결렬된다(§12, 확정 규칙).
- **플레이어 포기**: 라운드 소모와 무관하게 언제든 거래를 포기할 수 있다(§12).

### 5. 구매 처리 (§13)

- 손님이 수락하면:
  1. `GameState`에서 자금을 제안가만큼 차감한다.
  2. "구매 완료: {물건명} — {금액}원"을 표시한다.
- **Inventory 미존재 상태의 처리**: 구매한 물건은 어디에도 저장하지 않는다. 화면에
  결과만 보여주고 그 이후 물건 데이터는 버린다. 재고 슬롯·저장은 PRD 1-3에서 실제로
  연결한다(아래 "PRD 1-3과의 경계" 참고).
- **재고 부족 처리(§14) 미포함**: 실제 재고가 없으므로 9/9 초과 체크를 할 수 없다.
  이 PRD에서는 재고 부족으로 인한 거래 취소가 발생하지 않는다.

### 6. 거절/결렬 처리

- 플레이어 포기 또는 3회 소진 결렬 모두 "거래 종료(미성사)"로 동일하게 처리한다.
- 자금 변화 없음.

### 7. 손님 퇴장 및 다음 거래 준비

- 결과 표시 후 손님 정보가 화면에서 사라지고 거래 상태 기계는 `Idle`로 복귀한다.
- 이 PRD는 **손님 1명**만 다룬다. `Idle` 복귀 후 자동으로 다음 손님이 등장하지는 않는다.
- 반복 검증을 위해 PRD 1-1의 "개발용 영업시간 즉시 종료" 단축키와 같은 방식으로
  **개발용 "다음 손님 호출" 단축키**를 둔다. 여러 손님이 하루 동안 자동으로 이어지는
  루프는 이 PRD 범위 밖이다(아래 "범위 밖" 참고).

## 범위 밖

- 실제 Inventory 저장 / 슬롯 관리, 재고 9칸 제한 체크 (PRD 1-3)
- 하루에 4~5명 손님이 자동으로 순서대로 등장하는 루프 (개발용 수동 호출로만 재현)
- 시세 확인 및 보유 물품 판매(DAY 시작 판매창)
- 감정, 진품/가품(STAGE 1은 항상 진품)
- 손님 성격/가품 성향/신뢰도, 성향 기반 조기 결렬, 공격(STAGE 2)
- 물건 희귀도 가중치 추첨(§18) — 이 PRD는 균등 랜덤으로 대체
- 특수 아이템, 보따리 상인, 월세/정산, GAME OVER, STAGE 2
- 최종 UI 디자인, 아트, 사운드, 손님 대사 연출

## UI 배치 보완 (2026-08-19 플레이 피드백)

- 1280×720 기준으로 상단 상태, 남은 시간, 손님 대기열, 손님 정보, 제안 입력, 반응,
  거래 버튼을 서로 겹치지 않는 독립된 세로 구역에 배치한다.

- STAGE 2의 감정·방어 버튼은 기본 거래 버튼 아래 별도 행에 표시한다.

## 제안가 입력 보완 (2026-08-19 플레이 피드백)

- 손님이 등장하면 제안가 입력칸은 0원이 아니라 손님의 최초 희망 가격으로 시작한다.
- 제안가 입력칸 옆에 위·아래 화살표 버튼을 표시하고 한 번 누를 때마다 100원씩 증감한다.
- 키보드 위·아래 방향키도 같은 100원 증감 동작을 제공한다.
- 화면의 위·아래 화살표는 짧게 누르면 한 번만 증감하고, 450ms 이상 누르면 손을 뗄 때까지
  180ms 간격으로 반복 증감한다. 포인터가 버튼 밖으로 나가도 즉시 반복을 멈춘다.
- 새 거래에서 첫 숫자 키 입력은 초기 희망 가격을 덮어쓰고 이후 숫자는 이어서 입력한다.
- 화살표 버튼이나 키보드 방향키로 금액을 증감한 뒤 첫 숫자 키를 누르면 조정된 금액 뒤에
  붙이지 않고 해당 숫자부터 새 금액으로 초기화한다. 이후 숫자 키는 새 금액 뒤에 이어 붙인다.
- 제안가는 0원보다 작아질 수 없다.
- 화살표 버튼은 제안가 오른쪽에 `▼`·`▲` 순서로 가로 배치하고, 제안가와 함께 즉시
  식별할 수 있도록 작은 보조 문자보다 큰 18px 기호와 넓은 클릭 여백을 사용한다.
- 제안가 텍스트를 클릭하면 다음 숫자 키 입력이 현재 금액을 자동으로 덮어써 별도 삭제가 필요 없다.
- 제안가 컨테이너에는 현재 입력 금액과 별도로 `손님 제시가`를 작은 보조 글자로 고정 표시해,
  흥정 말풍선이 바뀐 뒤에도 최초 희망 가격을 비교할 수 있게 한다.
- 이 직접 입력 상태를 설명하는 별도의 하단 안내 문구는 표시하지 않는다.
- 보유 현금보다 높은 제안은 거래에 반영하지 않고 `제안 불가` 팝업으로 이유와 현재 보유
  현금을 안내한다. 팝업을 닫은 뒤 입력한 금액은 유지한다.
- 사용자 승인 시각 변경(2026-08-23): `제안 불가` 팝업은 감정 결과 팝업과 같은 검정 목재·
  얇은 황동 장식 프레임과 분리된 확인 버튼을 재사용한다. 제목, 실패 이유, 현재 보유 현금,
  확인 문구는 이미지에 포함하지 않고 런타임 텍스트로 표시한다. 같은 공통 이벤트 팝업을 사용하는
  공격 방어·손님 공격 안내도 동일한 프레임을 사용하되 각 이벤트의 문구와 동작은 유지한다.

  `제안가` 라벨과 금액은 기존보다 크게 표시한다.
- 사용자 승인 변경(2026-08-25): 현재 HUD 제안가 패널은 양옆 행동 버튼의 불투명 프레임 높이와
  맞도록 전체를 약 96.4%로 비례 축소한다. 최초 제시가·제안가 라벨·금액·증감 화살표도 같은
  비율로 축소하고 패널 중심을 기준으로 재배치한다.
- `매입 제안` 이미지 버튼은 현재 입력된 제안가를 제출하고, 긴 제안가 입력 영역을 누르면
  다음 숫자 입력이 현재 금액을 덮어쓰는 직접 입력 상태가 된다.
- 손님 설명 영역에는 이름·성향 힌트·물건 카테고리·희망가 문장을 중복 표시하지 않는다.
- 영업 중 상단의 기존 `STAGE · 영업 중` 영역은 현재 손님의 신뢰도를 표시하고,
  손님이 없는 순간에는 `신뢰도 --`를 표시한다. 영업 외 단계는 기존 STAGE·상태 문구를 유지한다.
- 감정·방어 결과는 해당 기능의 전용 피드백 영역에서 안내한다.
- 손님 캐릭터를 살짝 왼쪽으로 옮기고 오른쪽에 말풍선을 표시한다.
- 말풍선은 물건 이름과 최초 희망 가격을 반드시 포함하며, 손님의 동물 외형과 성격을
  반영한 고정 대사를 사용해 같은 손님을 다시 렌더링해도 문구가 바뀌지 않는다.
- 손님이 등장하면 말풍선 대사를 완성된 문장으로 즉시 표시하지 않고, 왼쪽부터 한 글자씩
  나타나는 타자기 효과로 출력한다. 출력 중 게임을 가리는 팝업이 열리면 효과도 함께 멈춘다.
- 글자당 출력 간격은 현재 45ms 테스트값으로 두고 `src/config/`에서 조정할 수 있게 한다.
- 타자기 출력 중 글자 수에 따라 문장 시작점이 이동하지 않도록 말풍선 내부에 최종 대사가
  들어갈 고정 영역을 먼저 확보하고, 그 영역의 왼쪽 위부터 글자를 채운다.
- 고정 영역은 완성될 전체 문장 블록의 너비와 높이를 기준으로 말풍선 가로·세로 중앙에
  배치하며, 각 줄은 최종 위치의 왼쪽부터 채워 이미 출력된 글자가 움직이지 않게 한다.

- 첫 제안 전에는 `손님 제안가 그대로 또는 금액 수정 후 매입 제안` 같은 조작 안내 문구를

## Customer / Item / GameState의 책임

- **GameState**: Stage/Day/Phase/Money만 소유. 거래 결과로 돈이 줄어드는 것은 GameState의
  책임이지만, 거래 자체의 규칙(라운드, 반응 판정)은 소유하지 않는다.
- **Customer**: 손님 자신의 데이터(제시 물건, 희망가, 최저 수용가)만 가진다. 흥정 로직을
  스스로 실행하지 않는다 — 순수 함수/거래 상태 기계가 Customer 데이터를 입력받아 반응을
  계산한다.
- **Item**: 물건 자체의 정적 데이터만 가진다. 로직을 갖지 않는다.
- **거래 로직**: Phaser Scene 밖의 순수 TypeScript 모듈이 라운드 진행, 반응 판정,
  성사/결렬 여부를 계산한다. Scene은 이 모듈을 호출하고 결과를 렌더링만 한다
  (PRD 1-1의 `GameState`/`DayScene` 관계와 동일한 패턴).

## 거래 상태 및 거래 흐름

```
Idle
  → (손님 등장) Presenting
  → (첫 가격 제안) Negotiating (round 1)
      → 수락 → Resolved(purchased)
      → 조금만/불만/강한 불만 & round < 3 → Negotiating (round+1)
      → 조금만/불만/강한 불만 & round == 3 → Resolved(brokenOff)
      → 플레이어 포기 (아무 라운드에서나) → Resolved(rejected)
  → (결과 표시 후) Idle
```

## 가격 제시 / 흥정 처리

- 위 "가격 제안 (§10, §11, §12, §13)" 절 참고. 반응 판정 임계값(90/70%)은 통합 기획서
  §11 표를 그대로 사용하는 확정값이다.

## 구매 시 자금 처리

- 거래 성사 시점에만 자금이 변한다. 흥정 도중에는 자금이 변하지 않는다.
- `GameState.spendMoney(offer)`가 잔액을 초과하지 않는지 방어한다 — 애초에 제안 단계에서
  현금 초과 입력을 막으므로 이중 방어에 가깝다.

## 거절 처리

- 플레이어의 명시적 포기와 3회 소진 결렬을 결과 화면에서는 모두 "거래 종료(미성사)"로
  동일하게 보여준다. 내부 `outcome`은 `rejected`/`brokenOff`로 구분해 두어 이후 신뢰도
  시스템(PRD 범위 밖)이 이 정보를 구분해서 쓸 수 있게 한다.
- 사용자 승인 변경(2026-08-23): 플레이어가 손님의 제안을 `거절하기`로 종료해도 신뢰도는
  감소하지 않는다. 일반 흥정 중 불만 반응과 재고 부족도 즉시 신뢰도를 깎지 않는다. 과도한
  흥정이 공격 또는 결렬로 거래 종료까지 이어진 경우에만 해당 거래에서 신뢰도를 5만큼 한 번
  감소시킨다. 거래 성사 시 신뢰도 상승은 기존 규칙을 유지한다.

## 거래 종료 / 손님 퇴장

- `Resolved(purchased)` 진입 시 손님 외형·말투에 맞는 거래 성사 대사를 기존 손님 말풍선의
  타자기 효과로 표시한다. 손님과 물건은 대사를 읽을 수 있는 현재 테스트값 4초 동안 유지한
  뒤 퇴장하고, 남은 손님이 있으면 별도 공백 없이 다음 손님이 입장한다.
- 플레이어가 거래를 거절해 `Resolved(rejected)`가 된 경우에도 손님 외형·말투에 맞는 거절
  대사를 같은 말풍선에 표시하고 현재 테스트값 4초 동안 유지한 뒤 다음 손님으로 전환한다.
  이때 하단 반응 영역의 `거래 종료 (미성사)` 중복 문구는 표시하지 않는다.
- 제안 횟수 소진 또는 위험 판정으로 `Resolved(brokenOff)`가 된 경우에도 모든 손님별 성격과
  말투에 맞는 전용 결렬 대사를 말풍선에 표시한다. 최초 제시 멘트를 반복하거나 하단에 공통
  결렬 문구를 중복 표시하지 않는다. 대사는 현재 테스트값 4초 동안 유지한다.
- 재고 부족으로 수락된 매입을 완료하지 못한 경우에는 먼저 재고 부족 팝업을 표시한다. 팝업을
  닫으면 손님 이름별 전용 대사를 말풍선 타자 효과로 처음부터 재생하고, 이름별 대사가 없는
  손님은 성격 유형별 기본 대사를 사용한다. 대사를 읽을 수 있도록 손님을 결과 표시 시간 동안
  유지한 뒤 퇴장시킨다.
- 그 외 `Resolved` 결과도 설정된 결과 표시 시간 후 `Idle`로 되돌아간다.
- `Idle` 상태에서는 개발용 단축키로 새 손님을 호출할 수 있다(자동 루프는 범위 밖).

## PRD 1-1과의 연결

- Phase 전이(`BeforeOpen`/`Open`/`Closed`)는 변경하지 않는다. 거래는 `Open` 동안에만
  발생하며, `Open`이 아닐 때는 손님이 등장하지 않는다.
- `Open` 진입 시(또는 진입 후 첫 손님 호출 시) 거래 상태 기계가 `Idle`에서 시작한다.
- `DayScene`에 손님/물건/가격 입력 UI를 추가한다. 새 Scene을 만들지 않는다
  (CLAUDE.md: 필요 이상으로 구조를 복잡하게 만들지 않는다).
- `GameState`는 `spendMoney` 메서드만 추가되고 기존 Phase 관련 동작은 그대로 유지된다.

## PRD 1-3과의 경계

- PRD 1-3(구매와 재고 연결)이 실제 Inventory를 만들고, 이 PRD의 "구매 완료 표시 후 버림"을
  "재고에 실제로 추가"로 대체한다.
- 재고 9칸 제한과 "재고 공간이 부족합니다" 처리(§14)는 PRD 1-3에서 Inventory와 함께
  구현한다.
- 이 PRD의 거래 로직(라운드/반응 판정)은 PRD 1-3에서 재사용되고, PRD 1-3은 그 위에 재고
  체크만 얹는다 — 거래 규칙 자체를 다시 만들지 않는다.

10. `npm run typecheck`, `npm run build`, `npm test`가 통과한다.

5. 구매 완료/거래 종료 표시가 결과를 명확히 전달하는가
6. 개발용 "다음 손님 호출"로 반복했을 때 밸런스 테스트값(희망가/최저수용가 비율,
   아이템 기준가)이 지나치게 쉽거나 어렵게 느껴지지는 않는가 — 초기 인상만 기록
