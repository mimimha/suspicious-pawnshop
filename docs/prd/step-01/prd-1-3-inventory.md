# PRD 1-3 — 구매와 재고 연결

> 출처: Notion `전당포 게임 > 통합 기획서` §13(거래 성사), §14(재고 부족), §15(재고),
> `재고·판매·시세 규칙` §1~2, §6~7, `물건·감정 규칙` §20~22,
> `거래·흥정 규칙` §10~13
> 스냅샷: 2026-08-18 (Notion 페이지 기준 시각 2026-08-18T14:47Z)
> 이전 PRD: `prd-1-2-customer-trade.md`

## 목표

PRD 1-2에서 거래 성사 후 버리던 구매 물건을 실제 Inventory에 저장한다. 플레이어는 영업 중
`매입품` 버튼으로 3×3 선반을 열어 보유 물건과 매입 가격을 확인할 수 있어야 한다. 재고가
가득 찼을 때는 거래 성사를 원자적으로 취소하여 현금과 재고가 모두 변하지 않아야 한다.

## 사용자에게 보이는 최소 플레이 흐름

```text
손님과 가격 합의
  → 재고 여유 있음: 현금 차감 + 물건 재고 추가 + 구매 완료
  → 재고 9/9: 별도 `거래 불가` 팝업으로 재고 부족 안내 + 현금 불변 + 거래 종료

[매입품] 버튼
  → 3×3 선반 팝업
  → 각 칸의 물건 확인
  → 물건 선택 시 이름 / 매입 가격 / 진품 여부 표시
  → 닫기
```

## 구현 범위

### 1. Inventory 시스템 — 순수 TypeScript

- Inventory가 자신의 물건 목록과 용량을 소유한다. `GameState`에 재고를 넣지 않는다.
- 기본 용량은 9칸이며 config에서 관리한다.
- 물건 1개는 정확히 1칸을 사용한다.
- 같은 종류의 물건을 여러 번 사도 서로 다른 `instanceId`를 가진 별도 항목으로 저장한다.
- 최소 API: `items`, `capacity`, `size`, `remainingSlots`, `isFull`, `canAdd()`, `add()`.
- 외부에서 내부 배열을 직접 변경할 수 없도록 읽기 전용으로 노출한다.

### 2. 보유 물건 데이터

PRD 1-2의 정적 `ItemSeed`를 그대로 재사용하고, 구매 시점 데이터만 별도 인스턴스에 둔다.

| 필드 | 타입 | 비고 |
| --- | --- | --- |
| `instanceId` | string | 같은 물건 종류도 구분하는 고유 ID |
| `item` | `ItemSeed` | 이름, 카테고리, 기준가를 가진 정적 데이터 |
| `purchasePrice` | number | 실제 합의한 매입 가격 |
| `authenticity` | `genuine` | STAGE 1은 항상 진품 |
| `purchaseRecord` | object | 매입 STAGE/DAY, 감정 확인 여부, 실제 확인한 시세 정보 |

가품/미감정 상태는 STAGE 2 범위이므로 이 PRD에서는 `genuine`만 허용한다. 기준가는 데이터에
남아 있지만 재고 UI에서 공개하지 않는다.

#### 사용자 승인 변경 — 거래 판단 기록

- 상세에는 매입가, 매입 STAGE/DAY, 매입 당시 진품 여부 확인 상태를 표시한다.
- 감정하지 않은 물건은 실제 진품/가품 값을 노출하지 않고 `미확인`으로 표시한다.
- 시세 정보는 자동 추정하지 않는다. 해당 물건에 시세 확인권을 사용했을 때 공개된
  `다음 DAY 예상 판매가`와 확인 STAGE/DAY만 기록하며, 미사용 물건은 `미확인`으로 표시한다.
- 사용자 승인 변경(2026-08-26): 예상 판매가·예상 손익 범위는 **어디에도 표시하지 않는다.**
  이 범위는 기준가에서 그대로 계산되므로 보여 주면 물건의 값을 알려 주는 것과 같다.
  한 번 매입한 물건의 값을 영구히 알게 되면 이후에는 그 값만 부르게 되어 흥정이 사라진다.
  이전 규칙은 감정한 물건만 범위를 기록하고 미감정은 `정보 부족`으로 표시하는 것이었으나,
  감정한 물건에서도 같은 문제가 생기므로 기록 자체를 없앤다.
  물건의 가치는 판매 결과와 시세 정보를 통해 플레이하며 익힌다.
- 시세 확인권으로 확인한 STAGE/DAY와 다음 DAY 실제 판매가는 판매 후 거래 기록에도 보존한다.
- 판매된 물건도 거래 기록에 남겨 매입 당시 정보와 실제 판매가·손익을 비교할 수 있게 한다.

### 3. 구매의 원자적 처리

- 가격이 수락되면 Scene이 먼저 `Inventory.canAdd()`를 확인한다.
- 공간이 있으면 같은 처리 흐름에서 `GameState.spendMoney(offer)` 후 Inventory에 추가한다.
- 공간이 없으면 자금을 차감하지 않고 물건도 추가하지 않는다.
- 재고 부족은 거래 미성사로 처리하고 별도 `거래 불가` 팝업에서 `재고 공간이 부족합니다.`를 표시한다.
- PRD 1-2의 `purchased` 결과가 재고 추가 성공을 의미하도록 연결한다.
- Inventory의 `add()`도 자체적으로 용량 초과를 방어한다.

### 4. 3×3 선반 팝업

- `DayScene`의 좌측 메뉴에 `매입품` 버튼을 둔다.
- 버튼을 누르면 현재 Scene 위에 참고 이미지와 같은 자주색·황동 프레임의 3×3 매입품
  진열장 팝업을 표시한다. 새 Scene은 만들지 않는다.
- 빈 칸과 찬 칸을 구분한다.
- 찬 칸에는 `public/assets/items/`의 실제 물건 이미지와 물건명을 함께 표시한다.
- 선택한 칸은 보라색 안쪽 테두리로 강조하고, 주변에 이름·매입 가격·진품 여부를 담은
  어두운 상세 카드를 표시한다.
- 팝업 상단에는 가방 아이콘과 `매입품` 제목, 우측에는 큰 `×` 닫기 버튼을 표시한다.
- 팝업 하단에는 `보유 슬롯 {현재} / {전체}`를 표시한다.
- 사용자 승인 변경(2026-08-23): 소형 매입품 창의 제목·슬롯명·수량·보유 슬롯 문구는 68% 좌표
  환산과 화면 전체 축소 뒤에도 읽을 수 있는 최종 크기로 렌더링한다. 제목은 기존 배경 에셋의
  인쇄 문구만 사용해 중복 표시하지 않으며, 슬롯명은 밝은 미색과 검은 그림자를 사용한다.
- 사용자 제공 레퍼런스를 기준으로 외곽 이중 황동 프레임과 코너 장식, 상단 통풍구 장식,
  어두운 목재 진열장, 슬롯별 안쪽 그림자와 선반 결을 Phaser Graphics로 구성한다.
- 물건 이미지는 슬롯의 대부분을 차지하도록 크게 표시하며 선택 슬롯은 보라색 벨벳 배경과
  금빛·보라색 이중 테두리로 강조한다.
- 매입품이 판매되거나 제거되면 남은 물건은 제거 직전 슬롯의 상대 순서를 유지한 채 첫 칸부터
  빈칸 없이 앞으로 자동 정렬한다.
- 상세 정보는 선택 슬롯 위에서 이웃 슬롯 방향으로 펼쳐지는 꼬리 달린 어두운 카드로 표시한다.
- 레퍼런스의 세로형 패널 비율을 유지해 1280×720 화면 중앙에 좌우 여백을 두고 표시하며,
  가로로 늘여 화면을 채우지 않는다.
- 제목·슬롯명·상세 정보·보유 슬롯 문구는 `Noto Serif KR`, `NanumMyeongjo`, `Batang`,
  `serif` 순서의 명조 계열 폰트를 사용한다.
- 사용자 승인 목업 기준으로 매입품 창의 외곽 프레임·빈 진열 슬롯·닫기 버튼을 각각 분리된
  UI 에셋으로 조립한다. 목업에 포함된 예시 물건 그림은 사용하지 않고
  `public/assets/items/`의 기존 매입품 이미지를 슬롯 위에 동적으로 표시한다.
- 같은 종류의 보유 수량은 별도 배지 컨테이너 없이 슬롯 우측 상단에 `x1` 형식의 런타임
  텍스트로 표시한다. 하단 가방 아이콘은 표시하지 않고 `보유 슬롯 {현재} / {전체}`를
  창 전체 폭 기준으로 중앙 정렬한다.
- 닫기 버튼은 승인 목업의 작은 정사각형 황동 프레임을 사용하며, 직전 시안 대비 프레임과
  `×`를 함께 80% 크기로 표시한다.
- 사용자 승인 변경(2026-08-23): 매입품 창의 외곽·헤더·닫기 버튼·슬롯·하단 장식은 영업 중
  아이템 창과 같은 검정 목재, 가는 낡은 황동선, 어두운 자주색 벨벳과 동일한 장식 밀도로
  다시 구성한다. 푸른 목재 띠, 밝고 두꺼운 금색 코너 장식, 선명한 자주색 슬롯은 사용하지 않는다.
- 3×3 구조와 기존 매입품 PNG, 런타임 물건명·`x1`·보유 슬롯 수, 선택·툴팁·드래그 동작은
  유지하며 아이템 창과 한 세트처럼 보이게 한다.
- 닫기 버튼 또는 동일한 `매입품` 버튼으로 팝업을 닫는다.
- 팝업이 열려 있어도 PRD 1-2 규칙대로 영업시간은 계속 흐른다.

### 5. 테스트를 위한 재고 채우기

- 개발 빌드에만 재고를 즉시 8/9까지 채우는 단축키를 제공해 마지막 한 칸과 9/9 거부를
  반복 검증할 수 있게 한다.
- 프로덕션 빌드에는 단축키와 안내 문구가 포함되지 않아야 한다.

## 범위 밖

- 물건 드래그 재배치와 위치 저장 (현재 Step 1 최소 흐름에는 게임 효과가 없음)
- 정렬, 필터, 희귀도 표시, 재고 확장
- DAY 시작 판매창, 시세 갱신, 물건 판매/삭제
- STAGE 2 진품·가품 생성, 감정/미감정 상태
- 선반 개폐 애니메이션과 추가 효과음
- 재고 팝업을 열었을 때 시간 정지

## 시스템 책임

- **GameState**: Stage/Day/Phase/Money. 자금 차감만 담당한다.
- **Inventory**: 보유 물건, 용량, 추가 가능 여부를 담당한다.
- **TradeSession**: 흥정 라운드와 손님 반응을 담당한다. 재고를 직접 참조하지 않는다.
- **DayScene**: 수락 시 Inventory와 GameState를 조정하고 결과를 렌더링한다.

Inventory가 GameState나 Phaser에 의존하지 않도록 해 단위 테스트할 수 있게 한다.

## 완료 조건

1. 거래 성사 시 보유 현금이 정확히 차감되고 물건이 Inventory에 1개 추가된다.
2. 같은 종류의 물건을 여러 개 사도 서로 다른 재고 항목으로 보관된다.
3. `매입품` 버튼에서 현재 재고 수량을 확인할 수 있다.
4. 3×3 선반 팝업에 9칸이 표시되고 구매한 물건이 찬 칸으로 보인다.
5. 물건을 선택하면 이름, 매입 가격, 진품 여부가 표시된다.
6. 재고 9/9에서 거래가 수락되면 별도 `거래 불가` 팝업에 `재고 공간이 부족합니다.`가 표시된다.
7. 재고 부족 거래에서는 현금과 Inventory가 모두 변하지 않는다.
8. 팝업을 열고 확인하는 동안에도 영업시간이 감소한다.
9. 재고 용량은 config에 정의되며 Inventory/Scene 로직에 `9`를 하드코딩하지 않는다.
10. `npm run typecheck`, `npm run build`, `npm test`가 통과한다.
11. 9개 슬롯의 보유 물건이 실제 매입품 이미지와 이름으로 표시된다. 물건에 마우스를 올리면
    사용자 참고 이미지와 같은 왼쪽 꼬리·검은 배경·황동 테두리의 툴팁에 이름, 매입가,
    진품 여부가 표시된다.
    사용자 승인 변경(2026-08-24): 모든 매입품 상세 툴팁의 이름은 기존 위치보다 10px 아래에
    표시해 상단 프레임과 충분한 여백을 둔다. 본문과 진품 여부 위치는 유지한다.
    툴팁이 카드 오른쪽에 뜨면 왼쪽 꼬리, 카드 왼쪽에 뜨면 오른쪽 꼬리를 사용해 꼬리 끝이
    현재 마우스를 올린 매입품 슬롯 가장자리를 가리킨다.
12. 앞 또는 중간 슬롯의 매입품을 판매하면 뒤쪽 매입품이 즉시 앞으로 이동해 빈 슬롯이 사이에
    남지 않는다.

## 자동 검증 항목

| # | 항목 | 방법 |
| --- | --- | --- |

| 2 | 물건 추가 | add 후 size/remaining/items 검증 |

| 7 | 재고 부족 연결 | 자금/재고 모두 불변 검증 |

## 사용자 플레이테스트 항목

1. 구매 직후 `매입품 1/9`로 바뀌는 것이 명확한가
2. 3×3 선반 팝업에서 빈 칸과 물건 칸이 한눈에 구분되는가
3. 물건 선택 정보가 매입 판단을 기억하기에 충분한가
4. 재고 9/9 거래 취소가 현금 미차감과 함께 명확히 전달되는가
5. 영업 중 팝업을 여닫는 조작이 거래 흐름을 방해하지 않는가
