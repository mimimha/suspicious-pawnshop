## 목표

수동 개발키로 한 명씩 불러오던 손님 거래를 실제 하루 영업 루프로 바꾼다. 영업을 시작하면 STAGE별로 정해진 방문 기회 안에서 각 거래 종료 후 다음 손님이 자동 등장한다. 플레이어가 직접 오늘 장사를 종료하거나 영업시간이 끝나면 진행 중 거래를 취소하고 더 이상 손님을 받지 않는다.

## 사용자에게 보이는 최소 플레이 흐름

```text
영업 시작
  → 첫 손님 즉시 등장
  → 거래 성사 / 결렬 / 거절
  → 짧은 대기 후 다음 손님 자동 등장
  → STAGE별 방문 인원을 모두 처리할 때까지 반복
  → 마지막 예정 손님 처리 완료 시 자동 장사 종료
    (또는 그 전에 플레이어가 종료하거나 시간이 끝나면 즉시 종료)
  → 일일 명세
```

## 구현 범위

### 1. CustomerQueue 시스템

- Phaser에 의존하지 않는 `CustomerQueue`가 등장 완료 수, 처리 완료 수와 다음 손님 대기 상태를 소유한다.
- STAGE 1은 DAY마다 5명, STAGE 2는 DAY마다 6명을 받는다.
- 첫 손님은 셔터가 완전히 열린 뒤 빈 매장과 기본 HUD를 잠시 보여 준 다음 디졸브로 등장한다.
  이 짧은 대기 동안 영업시간은 감소하지 않는다.
- 거래 성사, 결렬, 거절은 모두 해당 손님의 처리 완료로 기록한다. 거래 성사는 성향별 성사
  말풍선을 읽을 수 있는 결과 표시 시간이 지난 뒤 처리 완료로 전환하며, 남은 손님은 즉시
  다음 순서로 입장한다.
- 처리 완료 뒤 설정된 대기시간이 지나면 다음 손님을 등장 가능 상태로 만든다.
- 영업 종료 후에는 추가 손님을 만들지 않는다.

### 2. 영업시간 연결

- 손님 대기 중과 흥정 중에도 기존 영업 타이머가 계속 흐른다.
- 영업시간이 0이 되면 진행 중인 거래는 거래 없음으로 종료하고 물건·현금·재고를 변경하지 않는다.
- 영업 종료 뒤에는 대기 중이던 손님도 등장하지 않는다.
- 플레이어는 방문 기회가 남았거나 거래 중이어도 `오늘 장사 종료`를 선택할 수 있다.
- STAGE별 예정 방문 인원을 모두 처리하면 마지막 거래 결과 안내가 끝난 직후 장사를 자동 종료한다.
- 장사 종료 조작은 좌측 메뉴의 의미가 불분명한 화살표 대신 화면 왼쪽 하단 구석에
  `장사 종료` 문구가 보이는 독립 버튼으로 표시한다.
- 장사 종료 버튼은 `pawnshop-hud-v3/close-day.png` 에셋, 120px 폭,
  금빛 글꼴과 그림자를 사용한다. 높이는 옆 제안가 패널과 같은 108px로 맞춘다.

### 3. DayScene 표시와 자동 전환

- 영업 HUD에 오늘 전체 방문 수와 현재 방문 순서를 `오늘 방문 N / M명` 형식으로 표시한다.
- 별도의 구분점이나 `남은 N명` 문구는 표시하지 않는다.
- 방문 현황은 화면 중앙의 단독 문구가 아니라 오른쪽 상단 시간 패널 바로 왼쪽에 붙인
  동일 높이의 전용 박스 안에 표시한다.
- 방문 현황 박스의 가로 폭은 `오늘 방문 N / M명` 문구에 맞는 최소 폭으로 사용한다.
- 방문 현황과 시간 컨테이너는 `pawnshop-hud-v2`의 전용 HUD 프레임을 각각 현재
  크기에 맞춰 사용하고 금빛 HUD 글꼴로 통일한다.
- 두 컨테이너는 셔터가 덮는 영역의 오른쪽 경계 안쪽에 배치하며, 시간 박스 오른쪽에 15px,
  방문 현황과 시간 박스 사이에 10px 여백을 둔다.
- 대기시간이 끝나면 기존 거래 UI에 다음 손님과 물건을 자동으로 연결한다.
- 튜토리얼과 일반 영업을 포함한 모든 손님은 초상·말풍선·관찰 정보가 함께 짧은 디졸브로
  등장하고, 거래 종료 후에도 같은 방식으로 디졸브 퇴장한다.
- 거래 결과 안내 뒤 자동으로 대기 상태로 돌아간다.
- 기존 `N` 개발키는 일반 진행 수단에서 제외하고, 필요하면 대기시간만 즉시 끝내는 개발 보조 기능으로 제한한다.

### 4. 일일 초기화

- 다음 DAY 영업 시작 시 새로운 목표 방문 수와 카운터를 초기화한다.
- 전날의 진행 중 거래, 대기시간, 처리 수가 다음 DAY로 넘어가지 않는다.
- 기존 Market, Inventory, DailyLedger의 DAY 단위 데이터는 그대로 유지한다.

### 5. 연속 동일 손님 방지

- 손님 이름은 기존 13종 풀에서 무작위로 선택한다.
- 새 손님을 만들 때 직전에 방문한 손님의 이름은 후보에서 제외한다.
- 같은 손님은 이후 다시 방문할 수 있지만 두 거래가 연속으로 이어지지는 않는다.
- 직전 손님 기록은 DAY가 바뀌어도 유지해 전날 마지막 손님과 다음 날 첫 손님도 연속 중복되지 않는다.

## 범위 밖

- 손님별 성향, 이름, 신뢰도와 재방문
- 손님 공격, 병원비, 방패
- 손님별 등장 확률과 스테이지별 출현표
- 감정, 가품, 시세 확인 아이템
- 신규 캐릭터 이미지와 디졸브 외 별도의 이동 애니메이션
- 영업시간 증가 아이템

## 시스템 책임

- **CustomerQueue**: 하루 목표 인원, 등장/처리 카운터, 다음 손님 대기시간.
- **TradeSession**: 현재 한 명의 제안과 거래 결과. 큐 상태를 직접 소유하지 않는다.
- **GameState**: 영업 상태와 남은 시간.
- **DayScene**: 시스템 호출 순서, HUD와 거래 UI 전환.

## 완료 조건

1. 영업 시작 후 첫 손님이 즉시 등장한다.
2. 첫 손님은 자동으로 등장하고, 이후 손님은 이전 거래 종료와 대기시간 후 자동 등장한다.
3. 거래 성사·결렬·거절이 모두 처리 수에 정확히 한 번 반영된다.
4. STAGE 1은 5명, STAGE 2는 6명을 초과해 등장하지 않는다.
5. 대기 중과 흥정 중에 영업시간이 계속 감소한다.
6. 영업시간 종료 시 진행 중 거래가 취소되며 현금과 재고가 변하지 않는다.
7. 영업 종료 후에는 추가 손님이 등장하지 않는다.
8. HUD에서 전체 방문 수, 현재 진행과 남은 기회를 확인할 수 있다.
9. 다음 DAY에는 목표 수와 모든 큐 진행 상태가 새로 초기화된다.
10. 기존 거래·재고·정산·시세 테스트와 `npm run typecheck`, `npm run build`, `npm test`가 통과한다.
11. 현재 손님 다음에 같은 이름의 손님이 연속 등장하지 않는다.
12. 마지막 예정 손님의 거래 결과 안내가 끝나면 자동으로 장사를 종료하고 셔터 연출로 이어진다.

## 사용자 플레이테스트 항목

1. 첫 손님이 자연스럽게 등장하는가?
2. 다음 손님 대기 상태가 명확한가?
3. 전체 방문 수, 현재 순서와 남은 기회가 실제 흐름과 일치하는가?
4. 손님 사이 대기시간이 적절한가?
5. 언제든 사용할 수 있는 `오늘 장사 종료` 흐름이 이해되는가?
6. 흥정 중 시간 종료 처리가 납득 가능한가?

## 승인 시 확정되는 사항

1. STAGE 1은 DAY마다 5명, STAGE 2는 DAY마다 6명이 방문한다.
2. 첫 손님과 이후 손님 모두 별도 대기 없이 등장한다. 단, 직전 거래 결과는 1.8초 동안 표시한다.
3. 시간이 끝난 순간 진행 중 거래는 무효 처리한다.
4. 플레이어는 방문 인원 처리 여부와 관계없이 `오늘 장사 종료`를 선택할 수 있다.
5. 마지막 예정 손님을 처리하면 남은 시간과 관계없이 자동으로 장사를 종료한다.
